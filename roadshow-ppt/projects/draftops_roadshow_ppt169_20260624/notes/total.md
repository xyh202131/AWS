# 01_封面

这一页先给观众一个直观印象：DraftOps 不是一张静态名单，而是一个可以查看、复核、导出的项目交付驾驶舱。当前前端候选池是 123 人，本地答题候选池和球员特征记录都是 124 人；在线官方 Prospects 监控为 101 行，当前无变动。系统最终服务 30 顺位预测和 7 个里程碑答案。

# 02_项目重点

讲解范围收束为 DraftOps 项目本身：可信数据底座、多 Agent 文件流程、可解释预测引擎、产品界面和可导出提交物。

# 03_数据链路

我们的第一层工作是建立可信数据链路。官方 Prospects、前端候选池、本地答题池和外部来源先进入 raw 登记，再经过 normalized、clean、final、boards 多层产物，最后由前端读取和导出。当前状态里，30 个 pick 无重复，前端候选池 123 人，本地答题池 124 人，7 个里程碑答案都有对应文件承载。

# 04_多Agent协作

这里的 Agent 协作不是大家一起聊天，而是每个 Agent 负责一个清晰环节。数据采集不直接改结果，预测生成不直接采集来源，最终由 Supervisor 和提交检查把结构、证据、重复、空值和规则边界统一验收。

# 05_预测算法

算法逻辑可以讲得很直白：每个签位都在当前剩余候选池里重新评分，再按真实选秀顺序从第一顺位到第三十顺位依次选择。选中后移出候选池，所以不会重复。当前 relative run 覆盖 3255 次候选评审，最终 board 是 30 个 pick、30 名唯一球员、低置信为 0。

# 06_产品界面佐证

真实截图证明系统已经跑起来。左侧可以看到 30 顺位完整预测板，右侧可以看到单个球员的证据、风险、适配和来源。顶部导出的不是普通截图，而是 submission JSON 和项目摘要，直接服务最终提交。

# 07_AWS_RAG架构

AWS/RAG 层让系统不仅能展示结果，还能回答项目、数据、预测、里程碑和架构相关问题。当前 RAG manifest 是 5 个索引、1304 个保留 chunks、55 个来源；DynamoDB 同步 124 条球员特征记录，Lambda/API 作为只读问答入口。这里按可部署 API 层来讲，不把它夸大成已经完整 IaC 化的全量云原生平台。

# 08_收束

最后回到交付价值：我们提交的不是一段模型回答，而是一套可复核资产。它包括锁定的 30 顺位预测板、7 个里程碑答案、填好的答题卡、submission JSON、项目摘要、前端系统、代码仓库、RAG 同步和验证报告。
