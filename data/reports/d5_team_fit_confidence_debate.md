## Executive Recommendation

A5 correctly argues that team fit should matter more in a team-fit-heavy board, but D5 should not treat every `needs` label as equally reliable. The clean data report says 15 first-round picks are `needs_review`, and the final bundle preserves seed needs instead of appending unsupported review tags. Therefore, the safer design is not a single larger Team Need slider; it is a confidence-gated Team Need slider.

Recommended primary parameter set:

```json
{
  "consensus": 30,
  "need": 36,
  "player": 23,
  "upside": 6,
  "intel": 5
}
```

Use this only with a per-team need confidence coefficient. If the product cannot apply per-team coefficients yet, use the slider-only fallback:

```json
{
  "consensus": 34,
  "need": 28,
  "player": 24,
  "upside": 8,
  "intel": 6
}
```

Why D5 lowers A5's `need` from 40 to 36:

- Half of the first round is marked `needs_review`.
- `unknown` and `no_clear_need_source` must not become fake roster intelligence.
- `prediction.ts` already raises effective `need` for lottery, late-first, accelerate, and contend teams before normalization.
- A raw `need=40` can become a late-first/contender effective need above 50, which is too strong for low-confidence mixed signals.

## Team Need Weight Model

D5 recommends a two-step model:

1. Start with the global base weights: `C30 / N36 / P23 / U6 / I5`.
2. Let the existing draft-zone and team-phase logic calculate adaptive weights.
3. Apply the team need confidence coefficient to the adaptive `need` weight.
4. Redistribute the removed `need` weight to safer signals: 65% to `consensus`, 35% to `player`.

Formula:

```text
rawNeed = adaptiveWeights.need
trustedNeed = rawNeed * needConfidenceCoefficient
removedNeed = rawNeed - trustedNeed

adjusted.consensus = adaptiveWeights.consensus + removedNeed * 0.65
adjusted.need = trustedNeed
adjusted.player = adaptiveWeights.player + removedNeed * 0.35
adjusted.upside = adaptiveWeights.upside
adjusted.intel = adaptiveWeights.intel
```

The coefficient should be applied after zone/phase adjustment, not before it. Otherwise low-confidence late-first teams still get an inflated `need` score from the existing adaptive logic.

## How This Changes Selection Behavior

### Full-confidence teams

For Utah, Chicago, Sacramento, Milwaukee, Miami, Toronto, San Antonio, Detroit, Philadelphia, New York, and Minnesota, team need can decide between prospects in the same consensus tier. A guard-needy or shooting-needy team can move a clean-fit prospect several slots above another same-tier player if player grade and consensus are close.

This does not mean full-confidence need should override the top of the board. Picks 1-5 still need consensus and upside protection because `prediction.ts` already gives top-five picks extra consensus/upside weight.

### Medium but conditional teams

Washington, the LA Clippers, the Lakers, and Charlotte can use team fit, but the model should keep other signals close:

- Washington: `low_medium` fit should support AJ Dybantsa-style wing creation, not create a hard rule against another elite archetype.
- LA Clippers: asset context means young guard/shooting fit is useful, but upside and trade value remain part of the pick.
- Lakers: single-source need can elevate wing shooting/size, but should not bury a clearly better player.
- Charlotte: picks 14 and 18 should be sequenced. If one pick handles frontcourt, the second should not keep repeating the same frontcourt tags without new evidence.

### Review teams

For Memphis, Brooklyn, Atlanta, Dallas, Golden State, Oklahoma City, Denver, and Cleveland, D5 treats need as a tiebreaker or a narrative check, not a primary scoring engine.

Practical effects:

- Memphis pick 3 can still take a frontcourt hub if value and fit align, but pick 16 should not automatically repeat mixed frontcourt/guard tags.
- Brooklyn pick 6 should not be forced into a guard/wing archetype from contradictory sources; consensus and player grade should dominate.
- Atlanta picks 8 and 23 should not let one mixed guard/big/shooting label drive both choices.
- Dallas pick 9 and pick 30 can prefer shooting/creation in a tie, but the same mixed signal should not overrule stronger value.
- Golden State pick 11 should not be swung too hard by a low-confidence fit clue.
- Oklahoma City picks 12 and 17 should retain asset/stash optionality.
- Denver pick 26 and Cleveland pick 29 should avoid large reaches from frontcourt or creation tags alone.

### Unknown teams

Boston at pick 27 is the only first-round team with `confidence=unknown` and `status=no_clear_need_source`. Its listed final-bundle needs should be treated as seed roster labels, not current sourced need. The D5 coefficient is 0.00, so Boston should follow consensus, player grade, risk, and role quality. It should not steal a player from a later team merely because a generic `shooting` or `switchable forward` tag matches.

Manual override trigger: if a `needs_review` team produces a pick where the selected prospect is more than 5 consensus ranks away from the pick, require a written reason that does not rely only on the need label.

## Final Position

D5 supports making team fit important, but only for teams with usable need evidence. The board should not treat `needs_review` as a weak warning while still giving those teams the full Team Need slider. The correct parameter design is:

```text
global Team Need weight = 36
effective Team Need weight = adaptive Team Need weight * needConfidenceCoefficient
unknown/no_clear_need_source = 0.00 coefficient
removed unreliable need weight -> consensus/player
```

This keeps A5's intent for reliable teams while preventing low-confidence or unknown need labels from creating false precision in picks 6, 8, 9, 11, 12, 17, 23, 26, 27, 29, and 30.
